# Praise Tracker

A praise log with a dashboard. The page is hosted free on GitHub Pages, and the entries are saved to a Google Sheet you own. Everyone who has the link and the passcode shares the same entries.

**Files**

| File | Where it goes |
|---|---|
| `index.html` | GitHub repository |
| `config.js` | GitHub repository (after you paste in your URL) |
| `Code.gs` | Google Apps Script, not GitHub |
| `README.md` | GitHub repository (optional) |

Setup takes about 15 minutes. Do the steps in order.

> **Updating from the earlier version?** You don't need to redo setup. See [Updating to the version with contexts](#updating-to-the-version-with-contexts) at the bottom.

---

## 1. Set up the Google Sheet

1. Go to [sheets.new](https://sheets.new) to create a blank Google Sheet. Name it something like **Praise Tracker Data**.
2. In the sheet's menu, choose **Extensions → Apps Script**.
3. Delete the sample code in the editor, then paste in everything from `Code.gs`.
4. Near the top, change `'change-me'` to your passcode, for example `'amber-river-42'`. Keep the quotes.
5. Click the **Save** icon.

## 2. Publish the script as a Web app

1. In the Apps Script editor, click **Deploy → New deployment**.
2. Click the gear icon next to "Select type" and choose **Web app**.
3. Set **Execute as** to **Me**.
4. Set **Who has access** to **Anyone**. Visitors still need the passcode to read or add entries.
5. Click **Deploy**, then **Authorize access**, and choose your Google account.
   - If Google says the app isn't verified, click **Advanced → Go to (project name)**. This is your own script, so it's safe to allow.
6. Copy the **Web app URL**. It ends in `/exec`.
7. Open `config.js` in Notepad and paste the URL between the quotes in place of `PASTE_YOUR_WEB_APP_URL_HERE`. Save the file.

> If you edit `Code.gs` later, click **Deploy → Manage deployments → pencil icon → Version: New version → Deploy**. This keeps the same URL.

## 3. Put the page on GitHub Pages

1. Sign in at [github.com](https://github.com) and click **+ → New repository**.
2. Name it, for example `praise-tracker`. Choose **Public**, since free accounts can only publish Pages from public repositories. Click **Create repository**.
3. On the new repository page, click **uploading an existing file**. Drag in `index.html` and `config.js`, and `README.md` if you want it there. Click **Commit changes**.
4. Go to **Settings → Pages**. Under "Build and deployment", set **Source** to **Deploy from a branch**, choose **main** and **/ (root)**, and click **Save**.
5. Wait about a minute, then refresh. GitHub shows your link, which looks like:
   **`https://YOUR-USERNAME.github.io/praise-tracker/`**

## 4. Share it

Send people the link and the passcode separately. Each browser remembers the passcode after the first time it's entered.

To see all entries in a spreadsheet, open the Google Sheet and go to the **Entries** tab. You can also use **Download CSV** on the dashboard.

---

## Good to know

- **The code is public. The data is not.** Anyone can view the page's code on GitHub, but it doesn't contain the passcode or any entries. The Google script checks the passcode before it returns or saves anything.
- **Changing the passcode:** edit it in `Code.gs` and redeploy as a new version (see the note in step 2). Everyone is then asked for the new passcode.
- **Moving entries from the desktop version:** open the dashboard, click **Import CSV**, and choose your `praise_data.csv`. Rows that are already in the sheet are skipped.
- **Don't rename the Entries tab or its column headers**, or the tracker won't find its data. You can add rows or change existing ones directly in the sheet if they keep the same format: a date like `2026-09-29`, the type Effort, Intelligence or Skill, and the context Workplace, Interpersonal, Sexual or Other (or blank).
- **Work accounts:** if you use a Google Workspace account from your job, your admin may block **Anyone** access for web apps. If so, use a personal Google account.

## Updating to the version with contexts

This version adds a **Context** to each entry (Workplace, Interpersonal, Sexual or Other) and a new look. Your existing entries are kept.

1. **Update the script.** Open your Google Sheet, then **Extensions → Apps Script**. Before you paste, note the passcode currently on the `const PASSCODE` line. Replace all the code with the new `Code.gs`, put your passcode back on that line, and click **Save**.
2. **Redeploy it as a new version** so the link stays the same: **Deploy → Manage deployments →** pencil icon **→ Version: New version → Deploy**. Don't choose New deployment, because that creates a different URL.
3. **Update the page.** In your GitHub repository, click **Add file → Upload files**, drag in the new `index.html` (and this `README.md` if you keep it there), and click **Commit changes**. Leave `config.js` as it is. GitHub Pages updates within about a minute.

The first time someone saves an entry, the script adds a **context** column to the right of the existing columns in the Entries tab. Entries saved before this update show **Not set** on the dashboard. To give them a context, type Workplace, Interpersonal, Sexual or Other into that column in the sheet.

If the page still looks the old way, do a hard refresh (Ctrl+Shift+R, or Cmd+Shift+R on a Mac).
